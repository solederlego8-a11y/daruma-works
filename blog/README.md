# ブログの記事追加手順書

DARUMA WORKS（だるまワークス）のブログに、新しい記事を追加する方法をまとめた手順書です。
プログラミングの経験がなくても、「コピーして書き換える」だけで追加できるように作ってあります。

ブログのファイルは、このフォルダ（`blog/`）の中にあります。

| ファイル | 役割 |
|---|---|
| `index.html` | 記事一覧ページ（自動で一覧を作るので、基本さわらなくて大丈夫です） |
| `posts.json` | 記事の「目録」。ここに1件足すと、一覧ページに表示されます |
| `post-○○.html` | 記事1本ごとのファイル（例：`post-colors.html`） |

---

## 手順の全体像

1. 既存の記事ファイルをコピーして、新しい記事ファイルを作る
2. 中身（タイトル・日付・本文）を書き換える
3. 画像を用意して `images/` フォルダに入れる
4. `posts.json` に新しい記事の情報を1件追加する
5. ブラウザで表示を確認する

---

## ① 記事HTMLの作り方（コピーして書き換える方法）

1. このフォルダにある既存の記事ファイル（例：`post-colors.html`）をコピーします。
2. コピーしたファイルの名前を、新しい記事用に変更します（付け方は次の②を見てください）。
3. ファイルをテキストエディタで開き、次の場所を書き換えます。
   - `<title>…</title>` の中身 → 新しい記事のタイトル
   - `<h1>…</h1>` の中身 → 新しい記事のタイトル（`<title>` と同じ文でOKです）
   - `<time datetime="2026-10-28">2026年10月28日</time>` → 新しい記事の日付（`datetime` の数字と、表示される日付の両方を変えてください）
   - カテゴリ名が書かれた部分（`<span class="post-category">…</span>`）→ 新しいカテゴリ名
   - `<img src="../images/post-colors.jpg" …>` のファイル名 → 新しい画像のファイル名
   - `<p>…</p>` や `<h2>…</h2>` の本文 → 新しい記事の文章

**ポイント**
- `<style>…</style>` の部分（見た目の設定）はさわらないでください。デザインが崩れる原因になります。
- 見出しは `<h2>`（大見出し）と `<h3>`（小見出し）を使い分けると、読みやすい記事になります。
- 文章の段落ごとに `<p>` と `</p>` で囲むのが決まりです。

## ② ファイル名の付け方

- 形式は **`post-` のあとに、半角の英小文字とハイフン** を続けたものにしてください。
- 例：`post-care.html`、`post-gift-guide.html`、`post-newyear.html`
- 日本語、スペース、大文字は使わないでください（リンクが正しく動かなくなることがあります）。
- このファイル名から `.html` を除いたもの（例：`post-care`）が、次の③で使う「slug（スラッグ）」になります。

## ③ posts.json への追記方法

`posts.json` は記事の目録です。**新しい記事は一番上（一番最初）に追加してください。** 一覧ページは、ファイルに書かれた順番どおりに表示します。

既存の1件分をコピーして、次のように書き換えるのが一番簡単です。

```json
{
  "slug": "post-care",
  "title": "だるまのお手入れ方法 ― ほこりと日焼けから守るには",
  "date": "2026-11-05",
  "category": "お手入れ",
  "excerpt": "長く飾るためのほこりの取り方や、直射日光を避ける理由など、だるまをきれいに保つコツを紹介します。",
  "thumb": "../images/post-care.jpg"
},
```

各項目の意味は次のとおりです。

| 項目 | 書く内容 |
|---|---|
| `slug` | ファイル名から `.html` を除いたもの（例：`post-care`） |
| `title` | 記事のタイトル（記事HTMLの `<h1>` と同じ文） |
| `date` | 公開日。`2026-11-05` のように「年-月-日」の半角数字で書きます |
| `category` | カテゴリ名（記事HTMLに書いたものと同じ文） |
| `excerpt` | 一覧ページに出る短い紹介文（60〜100文字くらいが目安） |
| `thumb` | 画像の場所。`../images/` のあとに画像のファイル名を書きます |

**よくある間違い（表示されなくなる原因）**
- 項目のあとのカンマ（`,`）の付け忘れ・付けすぎ
  - 最後の1件以外は、閉じカッコ `}` のあとにカンマが必要です。
- 文字列を囲むダブルクォート（`"`）の閉じ忘れ
- 全角の記号を使ってしまう（記号はすべて半角で書いてください）

書き終わったら、ファイル全体が `[` で始まり `]` で終わっているかも確認してください。

## ④ 画像の置き場所

- 記事の画像は、サイトの **`images/` フォルダ**（`blog/` の1つ上の階層にある `daruma-site/images/`）に入れてください。
- ファイル名は記事とそろえると分かりやすくなります。
  - 例：記事が `post-care.html` なら、画像は `post-care.jpg`
- 記事HTML側では `../images/post-care.jpg`、posts.json 側でも `"../images/post-care.jpg"` と書きます（`../` が付くのは、ブログのフォルダから見て1つ上のフォルダを指すためです）。
- 画像は横長（目安は横1200px程度）で、容量が大きすぎないもの（1枚あたり数百KB程度まで）がおすすめです。

## ⑤ 公開前にブラウザで確認するポイント

公開（アップロード）する前に、次の5点を確認してください。

1. **一覧ページに新しい記事のカードが出ているか**（出ていないときは、③の posts.json の書き方を見直してください）
2. **カードをクリックして、記事ページが開くか**
3. **記事のタイトル・日付・カテゴリが正しいか**
4. **画像が表示されているか**（表示されないときは、画像のファイル名と置き場所を確認してください）
5. **スマホくらいの細い画面でも文字がはみ出していないか**（ブラウザのウィンドウを細くして確認できます）

> **ローカル確認時の注意**
> パソコン上でファイルを直接ダブルクリックして開くと、一覧ページの記事読み込み（fetch という仕組み）がブラウザの安全制限で動かず、「記事一覧を読み込めませんでした」と表示されることがあります。これは故障ではありません。
> ローカルで正しく確認したいときは、簡易サーバー経由で開くのが望ましいです。たとえば、このフォルダで `python3 -m http.server` を実行し、ブラウザで `http://localhost:8000/` を開くと、一覧も含めて実際の表示を確認できます。

---

## 困ったときは

- 一覧が真っ白・エラーになる → まず posts.json のカンマとクォートを確認してください。原因のほとんどはここです。
- デザインが崩れた → 記事HTMLの `<style>…</style>` をさわっていないか確認し、必要なら既存記事のファイルからその部分だけをコピーし直してください。
